# Integrations and compatibility

In **Source content**, you select an installed, approved plugin capability before choosing a source folder. Approving a package, approving a runtime, and authorizing each individual execution are separate steps. The bundled plugin profile ships with the packages listed below; building from source without bundling those resources does not fall back to a built-in implementation. See [plugin installation](plugin-distribution.md) for details on managing packages.

|---|---|---|---|

## WebVTT Caption Profile 1

The experimental WebVTT integration implements Caption Profile 1, a focused editing subset of the [W3C WebVTT syntax](https://www.w3.org/TR/2026/CRD-webvtt1-20260520/#syntax) (rather than a full WebVTT media renderer):

- **Accepted syntax and limits**: Input files must be UTF-8 (with an optional BOM) using LF, CRLF, or CR line endings, up to 128 KiB and 2,000 cues in total, with each individual cue text up to 16 KiB. Every cue requires a nonempty ASCII identifier (IDs differing only by ASCII case are rejected as duplicates, while original casing is preserved) and plain-text payloads (which may span multiple lines).
- **Timing and cue settings**: Timestamps use `mm:ss.mmm` or `hh:mm:ss.mmm` with non-decreasing start times and end times strictly after start times; overlapping cues are allowed. Supported cue settings are `line`, `position`, `size`, `align`, and declared `region`. `NOTE` blocks and leading `STYLE` or `REGION` blocks are preserved as original file data (embedded CSS is never executed by the workbench).
- **Rejected constructs**: Anonymous cues, cue payload markup or HTML entities, vertical cue settings, unrecognized settings, invalid timestamps, and empty cue payloads are rejected.

### Editing, building, and maintaining WebVTT subtitles

1. **Translate and review**: After importing and applying a source snapshot, edit cue translations under **Translations → Edit translations**, run checks and record approvals in **Review and QA**, or import existing translated `.vtt` files through the workflow in [translation import](translation-import.md).
2. **Build and export**: **Build and export** combines the saved source template with your approved project translations. It replaces only the cue text payloads while preserving timing, cue settings, identifiers, cue ordering, and all other original bytes, without rereading external subtitle files. Enter a valid `.vtt` filename for each target language; empty translations, blank lines, timestamp arrows (`-->`), or markup that could alter the file structure are rejected before a release can be created.
3. **Update source subtitles**: Choose **Update source content** to compare a new `source.vtt` snapshot. Unchanged cues retain their existing work, while timing or layout modifications require re-verifying source correspondence and review even if the source words are identical. Cues with renamed IDs do not inherit identity automatically from matching text alone. Confirming the continuation appends a new source revision while preserving earlier snapshots, translations, and releases.

## Skyrim SE development package

`skyrim-se 0.1.0-alpha.1` is a separate development package for Apple silicon macOS. Use a Native Host and Process 4 worker matched to SDK `0.1.0-alpha.9` and the worker's self-contained format component using codec protocol 5. The extractor identifies unsupported TES4 form versions and asks for a Skyrim Special Edition plugin with form version 44. The complete desktop bundle includes WebVTT and SMAPI. Check the Skyrim package identity in **Settings → Extensions** before enabling it and approve the native Host and individual executions through the usual controls.

- **Input** — Select the groups that apply to your Mod. A capture can include one embedded-text or localized ESP, ESM or ESL, the matching `.STRINGS`, `.DLSTRINGS`, and `.ILSTRINGS` tables referenced under `Strings/`, and up to sixteen SkyUI MCM tables under `Interface/Translations/`. Use files from the same Mod version and file-language variant, within 128 MiB per plugin or strings table, 16 MiB per MCM table and a combined 256 MiB raw limit. If the required tables are inside a BSA, extract them with a Skyrim SE archive reader into a separate folder, preserving their paths under `Strings/` or `Interface/Translations/`. Select the extracted files for capture and independently check the source before applying it.
- **Scope** — The declared fields include names, descriptions, books, quest objectives and logs, dialogue, message buttons, faction ranks, and selected perk text. Shared Strings IDs are edited as a single value. Script resources, undeclared fields, and XML exchange are outside this native workflow. Capture counts describe the declared projection.
- **Reuse and maintenance** — In **Entries → Import translations**, choose record text or MCM and capture the translated files against their adopted same-version original. For record text, the package checks that the native fields and nontext content match. Compare the independently checked suggestions before adopting them. For a new upstream version, use **Update source content** and review uncertain matches in the same project. Earlier development captures made with the old domain basis must be re-extracted to use the new worker for review or build.
- **Build and install** — Run the required format checks and record human approvals. In **Delivery**, select the game loading language separately from the target translation locale. Export the independently checked files to a new directory, keeping the plugin, matching tables, relative paths, and companion report together. Use a separate entry in the Mod manager and keep the original version. A same-named output plugin replaces that file in the selected load order, so check the intended base and any patches before enabling it.

On Apple silicon macOS, the desktop app imported a synthetic 64 MiB embedded ESP with 50,000 BOOK fields. After independent source checking and adoption, it built and independently checked an output retaining all 50,000 source fields. The exported ESP matched the input byte for byte. The companion report recorded the retained-source scope, and the project showed the same export receipt after reopening. A smaller synthetic two-version Mod covered existing translation reuse, reviewed translations and exporting each version. Mixed-file Mods at the larger scale, Windows desktop processing, and loading or displaying these outputs in Skyrim SE remain unverified. See the [offline Core and Worker tests](../crates/plugin-host/README.md#skyrim-se-conformance) for reproducible sample runs.

## Execution model and version compatibility

Executable plugins run through native or JavaScript Host channels and require explicit unsandboxed execution consent per attempt. Because plugin processes run with the current OS user's permissions, package capability declarations and Core grants act as application-level controls rather than an operating-system sandbox. Uninstalling or revoking a plugin preserves existing project records and never transfers prior permissions to a replacement package.

Core project and storage interfaces and Tauri capability bindings are internal. Each operation requires supported versions for its capability and exchanges. New attempts record the exact implementation versions used, and saved releases preserve their original artifact bytes and check proofs. See the [README](../README.md#development) for database schema compatibility and the [versioning policy](versioning.md) for application release versioning.
